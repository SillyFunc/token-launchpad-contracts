# 四通道税收分配说明与交易示例

## 一、核心概念

代币的税收配置分成两个层次：

1. **买税和卖税**：决定一笔交易收取多少税。
2. **四通道比例**：决定收取的税如何分配。

计算关系：

```text
交易税 = 交易数量 × 买税或卖税

通道份额 = 交易税 × 对应通道比例
```

四个通道的比例必须满足：

```text
marketBps + deflationBps + lpBps + dividendBps = 10,000
```

其中：

```text
10,000 bps = 100%
1,000 bps  = 10%
100 bps    = 1%
```

---

## 二、四通道的含义

| 通道 | 参数 | 创建者视角 | 实际处理方式 |
|---|---|---|---|
| 市场通道 | `marketBps` | 创建者收入或自动回购资金 | 税代币兑换为 BNB，发送给固定市场收款地址 |
| 销毁通道 | `deflationBps` | 减少代币流通量 | 税代币直接发送至 `0xdead` |
| LP 通道 | `lpBps` | 永久增加交易池流动性 | 一半保留为代币，一半兑换为 BNB，组成 LP 后永久销毁 |
| 分红通道 | `dividendBps` | 奖励符合条件的持币用户 | 税代币兑换为 WBNB，存入 Dividend 合约供持币人领取 |

---

## 三、市场通道

市场通道是唯一可能直接成为创建者收入的通道。

### 普通创建模式

使用普通 `createToken` 创建代币时：

```text
市场通道 → feeRecipient
```

如果 `feeRecipient` 是创建者钱包，创建者就会收到市场通道兑换得到的 BNB。

### 自动回购金库模式

使用 `createTokenWithVault` 创建代币时：

```text
市场通道 → BuybackVault → 自动回购
```

此时 Coordinator 会自动把市场收款地址替换为回购金库。

因此，自动回购不是第五个通道，而是市场通道的一种用途：

```text
普通模式：
市场通道 → 创建者钱包

金库模式：
市场通道 → 自动回购金库 → 回购代币或 LP 并销毁
```

金库模式要求：

```text
marketBps > 0
```

否则创建交易会失败。

## 四、销毁通道

销毁通道不经过 PancakeSwap，也不会兑换为 BNB。

处理方式：

```text
税代币 → 0x000000000000000000000000000000000000dEaD
```

这部分代币会直接退出正常流通。

例如：

```text
本轮收税：300 枚
销毁比例：10%

直接销毁：300 × 10% = 30 枚
```

销毁通道的主要作用是形成持续通缩。

---

## 五、LP 通道

LP 通道用于永久增加 PancakeSwap 交易池的流动性。

假设 LP 通道分到 60 枚税代币：

```text
30 枚代币保留
30 枚代币兑换为 BNB
```

随后使用：

```text
实际进入 Pair 的代币 + 对应数量的 BNB
```

组成新的 LP。

生成的 LP Token 会直接铸造给：

```text
0x000000000000000000000000000000000000dEaD
```

因此这些 LP：

- 创建者不能提取；
- 管理员不能提取；
- Keeper 不能获得；
- 不会进入任何个人钱包；
- 相当于永久锁定流动性。

代币转入 Pair 时可能再次产生卖税。合约会读取 Pair 的实际到账量，再计算所需 BNB，不会按照名义转账数量盲目加池。

产生的二次税会进入下一轮税收处理，不会丢失。

---

## 六、分红通道

分红通道会把对应税代币兑换为 WBNB，并存入每个代币独立的 Dividend 合约。

创建者需要配置：

```text
dividendBps
minimumShareBalance
```

例如：

```text
dividendBps = 3000
minimumShareBalance = 10,000 枚
```

表示：

- 税收的 30% 用于持币分红；
- 持有至少 10,000 枚代币的地址才参与分红。

分红按照有效持仓比例计算。

以下地址不会参与分红：

- PancakeSwap Pair；
- TaxProcessor；
- 代币合约自身；
- Dividend 合约；
- `0xdead`；
- 零地址。

用户可以调用：

```solidity
withdrawDividends()
```

领取自己的分红。因为当前分红资产是 WBNB，领取时会自动解包为 BNB。

如果暂时没有符合条件的持币人，分红资金不会被重新分给创建者或其他通道，而是保留在 TaxProcessor 中等待后续重试。

## 七、完整交易示例

假设创建者配置：

```text
买税：2%
卖税：3%

市场通道：40%
销毁通道：10%
LP 通道：20%
分红通道：30%
```

对应参数：

```text
buyTax       = 200
sellTax      = 300

marketBps    = 4000
deflationBps = 1000
lpBps        = 2000
dividendBps  = 3000
```

四通道合计：

```text
4000 + 1000 + 2000 + 3000 = 10,000
```

### 用户卖出 10,000 枚代币

卖税为 3%，因此：

```text
收取税代币 = 10,000 × 3%
           = 300 枚
```

四通道分配结果：

| 通道 | 比例 | 分配数量 |
|---|---:|---:|
| 市场 | 40% | 120 枚 |
| 销毁 | 10% | 30 枚 |
| LP | 20% | 60 枚 |
| 分红 | 30% | 90 枚 |
| 合计 | 100% | 300 枚 |

### 第一步：直接销毁

```text
30 枚 → 0xdead
```

销毁通道不参与兑换。

### 第二步：拆分 LP 通道

LP 通道的 60 枚分为两部分：

```text
30 枚保留用于加池
30 枚进入兑换
```

### 第三步：合并兑换

本轮需要兑换的代币为：

```text
市场：120 枚
LP：   30 枚
分红： 90 枚
----------------
合计：240 枚
```

这 240 枚会在一次清算中兑换为 WBNB。

这样可以减少交易次数和额外价格冲击。

### 第四步：分配兑换所得

假设这次兑换实际得到：

```text
2.4 BNB
```

按照参与兑换的代币数量分配：

#### 市场通道

```text
120 ÷ 240 = 50%

市场所得 = 2.4 × 50%
         = 1.2 BNB
```

#### LP 通道

```text
30 ÷ 240 = 12.5%

LP 所得 = 2.4 × 12.5%
        = 0.3 BNB
```

#### 分红通道

```text
90 ÷ 240 = 37.5%

分红所得 = 2.4 × 37.5%
         = 0.9 BNB
```

最终结果：

| 通道 | 最终处理 |
|---|---|
| 市场 | 约 1.2 BNB 发给创建者钱包或回购金库 |
| 销毁 | 30 枚代币直接销毁 |
| LP | 约 30 枚代币和 0.3 BNB 组成 LP，LP 永久销毁 |
| 分红 | 约 0.9 WBNB 存入 Dividend 合约 |

这里的 `2.4 BNB` 只是演示数字。真实兑换结果取决于：

- PancakeSwap 池储备；
- 实际成交价格；
- 卖税造成的实际到账差异；
- 滑点；
- Keeper 的最低输出保护；
- 交易时的价格波动。

## 八、创建者收入的理解方式

假设：

```text
卖税 = 3%
市场通道 = 40%
```

那么市场通道对应的理论比例是：

```text
3% × 40% = 1.2%
```

也就是说，用户每卖出价值 100 BNB 的代币，理论上有相当于约 1.2 BNB 的税收价值进入市场通道。

但这不是固定收益，实际收入还会受到成交价格、滑点和池深度影响。

其他通道的价值分别是：

```text
卖出交易额 × 3% × 10% → 通缩销毁
卖出交易额 × 3% × 20% → 永久 LP
卖出交易额 × 3% × 30% → 持币分红
```

## 九、创建时需要注意的规则

### 四通道比例

```text
marketBps + deflationBps + lpBps + dividendBps
必须精确等于 10,000
```

允许某些通道为零。

例如，全部进入市场：

```text
marketBps    = 10000
deflationBps = 0
lpBps        = 0
dividendBps  = 0
```

全部用于销毁：

```text
marketBps    = 0
deflationBps = 10000
lpBps        = 0
dividendBps  = 0
```

### 分红门槛

未启用分红时：

```text
dividendBps = 0
minimumShareBalance = 0
```

启用分红时：

```text
dividendBps > 0
minimumShareBalance > 0
```

### 回购金库

启用回购金库时：

```text
marketBps > 0
```

只有市场通道会进入回购金库，销毁、LP 和分红通道不会被金库占用。

### 配置不可修改

代币创建后，以下配置永久固定：

- 买税；
- 卖税；
- 四通道比例；
- 市场收款地址；
- 分红门槛；
- 是否使用回购金库。

如果配置错误，只能重新创建代币。

---

## 十、一句话总结

```text
市场通道解决“收入给谁”，
销毁通道解决“如何通缩”，
LP 通道解决“如何永久增加流动性”，
分红通道解决“如何奖励持币用户”。
```

创建者真正需要决定的是：

```text
我希望税收更偏向收入、回购、通缩、流动性，还是持币激励？
```
